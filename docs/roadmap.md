## 7. Lighthouse Phase 12 — comparaison et écart CSP expliqué

Rapports : `docs/audits/lighthouse/home-{mobile,desktop}-phase12.report.{html,json}`.

| Catégorie      | Mobile (Phase 3 → 12) | Desktop (Phase 3 → 12) |
| -------------- | --------------------- | ---------------------- |
| Performance    | 96 → 89               | 100 → 100              |
| Accessibility  | 100 → 100             | 100 → 100              |
| Best Practices | 100 → **92**          | 100 → **92**           |
| SEO            | 100 → 100             | 100 → 100              |

**Écart Best Practices (100→92), expliqué** : causé par la nouvelle CSP (`next.config.mjs`). Lighthouse détecte un appel `eval()` bloqué par `script-src`, dans un chunk interne à Next.js (`_next/dist/...`), avec ce message de React lui-même : _"React requires eval() in development mode... React will never use eval() in production mode"_. Vérifié en conditions réelles : **zéro erreur console** sur 11 routes + interactions (menu mobile), y compris avec throttling CPU 4x reproduisant les conditions Lighthouse. Conclusion : artefact spécifique à l'instrumentation Lighthouse, pas un problème rencontré par un visiteur réel. Décision : ne pas ajouter `'unsafe-eval'` à la CSP pour ce score — l'affaiblissement de la protection XSS ne se justifie pas pour un problème non reproductible en usage normal. À revisiter si un vrai symptôme utilisateur apparaît.

**Écart Performance mobile (96→89)** : mesure isolée, à confirmer sur une prochaine mesure avant de l'attribuer à un changement précis (aucun changement de cette phase ne devrait avoir d'impact perf — CSP/canonical/JSON-LD sont sans coût runtime notable).
